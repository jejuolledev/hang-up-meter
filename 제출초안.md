## Project name
Hang Up Meter

## Overview
An unfamiliar caller can make an urgent request sound routine. Hang Up Meter helps the listener pause and inspect what was actually asked: the caller’s words, a concerning request, and relevant consumer guidance in one view.

Type a fictional English conversation with Caller and Recipient labels, then check it with Clocked. The app distinguishes concerning requests, requests needing review, insufficient context, and no flagged signals. Optional source checks compare an explicit claim with selected FTC guidance. Neither a quiet result nor a source match authenticates the caller.

Three fictional sample calls can be played with synthetic speech or viewed without sound. Their results are written in advance and labeled separately from live checks. Browser transcription is optional, requires consent, and requires reviewing the text and adding speaker labels before analysis. Real-call microphone performance has not been validated.

## Clocked integration
- Decide assesses the current caller’s requests and controls the assessment shown to the listener.
- Extract identifies exact words from the supplied conversation. Unmatched text is rejected rather than displayed as a quotation.
- Rerank selects relevant material from two curated FTC excerpts. If more context is needed, the app reports that limitation rather than inventing a source.
- Grounding compares a specific factual claim with the selected excerpts. A request to buy a gift card is treated separately from a claim that government agencies require gift cards.

The gift-card example passed a live check and a browser check showing the warning, matching words, FTC guidance and claim comparison. Other source outcomes have fixture coverage and are not all claimed as live-tested. Fill and Protect are not implemented.

## Evidence and limitations
A frozen, authored English evaluation covered 40 conversations at three cumulative turns each: 20 risk conversations and 20 controls. All 20 risk conversations were detected without early alerts; one control conversation produced a false warning. A response-read failure was recovered with the original request ID and remains in the evaluation history.

The false alert involved a recipient recalling an earlier suspicious call without a current Caller turn. After evaluation, the app was changed to return insufficient context for that input without an API call. A fresh four-case live check passed; the original benchmark result has not been rewritten or presented as a new perfect score.

Across the 119 successful non-recovery requests, median Decide request time was 932 ms and nearest-rank p95 was 2312 ms. These figures exclude the recovered request and do not measure audio or the complete source-check chain. The examples are synthetic and are not independent real-world validation.

As of November 6, 80 automated tests pass, with the full HTTP-based run reported in the deployment record. Three synthetic live checks on the public app also passed: a gift-card request with FTC source comparison, an ordinary account message, and insufficient context. Browser checks covered input validation, clearing results, and a disconnected-network failure. Chrome sample playback was checked; physical speaker listening and full screen-reader testing remain unverified.

## What we learned
A risky request and a factual assertion require different checks. The app should help someone pause at a request for codes even when there is no factual claim to verify. When a caller also asserts an agency payment policy, showing the original words alongside the relevant source gives the listener a more concrete reason to stop and check independently.

The evaluation also exposed why speaker labels matter: someone describing an earlier call is not necessarily making the same request now. We retained the false alert in the results and added a targeted application safeguard.
